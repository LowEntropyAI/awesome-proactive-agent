# Assistance or Disruption? Exploring and Evaluating the Design and Trade-offs of Proactive AI Programming Support

## Why It Matters

This paper is a human-factors anchor for proactive coding assistants. It shows that proactive support is valuable only when it respects developer timing, control, and workflow continuity; otherwise the same capability becomes an interruption.

## Proactivity Signal

Codellaborator monitors editor activity and task context, then decides when to surface assistance without waiting for an explicit prompt. The proactive signal is therefore a mix of programming context, user activity, and inferred need for help.

## Evaluation Setup

The study compares prompt-only assistance, proactive assistance, and proactive assistance with richer presence/context cues in a within-subject user study. The main evidence comes from developer behavior, perceived usefulness, interruption cost, and acceptance of proactive suggestions.

## Key Limitations

The evaluation is a controlled study with a small developer sample and short programming tasks. It is most useful for interaction design principles, not for claiming long-term productivity gains in real software projects.

## Use For

Use this paper when designing IDE agents, notification policies, frequency controls, explanation surfaces, or evaluation rubrics that need to capture both task benefit and disruption cost.
